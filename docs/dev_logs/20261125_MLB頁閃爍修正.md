# 收工日誌 (Dev Log) - 2026-11-25 (MLB 頁閃爍修正)

## 📌 目標
- 修正第一次點 MLB 頁時整個 app 視窗消失一瞬的問題。

## 📌 原因
- QWebEngineView 是 RHI 元件。第一次真正顯示時，Qt 會銷毀並重建 top-level 視窗（native surface 重建、winId 改變），使用者看到整個 app 消失一瞬。
- 這與 QWebEngineView 何時建立無關，啟動時就建立也一樣會重建。

## 📌 第一次嘗試（無效，已還原）
- 把 `QWebEngineView` 提早到 `MlbView.init_ui()` 建構時建立。實測視窗仍會重建，且拖慢啟動，已還原 `ui/mlb_view.py` 與 `docs/architecture.md`。

## 📌 最終修法
- `main.py` 在匯入 PyQt6 之前設定 `os.environ.setdefault("QT_WIDGETS_RHI", "1")`，讓所有 widget 視窗一開始就用 RHI 合成，之後顯示 QWebEngineView 不需重建視窗。用 `setdefault` 讓使用者仍可用環境變數覆寫。

## 📌 診斷方式與結果
- 以診斷腳本監看 top-level 視窗的 PlatformSurface 與 WinIdChange 事件。
- 未設定時：切到 MLB 頁出現 SurfaceAboutToBeDestroyed → SurfaceCreated，且 winId 改變。
- 設定 `QT_WIDGETS_RHI=1` 後：整個過程視窗不再重建。

## 📌 測試 conftest 修正
- `QApplication([])`（空 argv）時呼叫 `QWebEngineView.page()` 會讓 Chromium 原生崩潰（exit -1073740791）；改用非空 argv 即正常。
- `tests/conftest.py` 的 `_session_qapplication` 改為 `QApplication.instance() or QApplication(sys.argv[:1] or ["pytest"])`，並加註解。正式 app（`main.py`）使用 `sys.argv`，不受影響。

## 📌 驗證狀態
- 診斷腳本層級已驗證視窗不再重建。
- app 實機尚待使用者確認；需留意 toast 半透明視窗等其他視窗外觀在 RHI 合成下是否正常。

## 📌 網頁載入前白底
- 原因：`QWebEngineView` 在網頁載入完成前，預設以白底繪製，深色主題下第一次進 MLB 頁會看到一瞬間刺眼的白。
- 修法：`ui/mlb_view.py` 的 `ensure_loaded()` 建立 `web_view` 後、`setUrl` 前呼叫 `self.web_view.page().setBackgroundColor(QColor(theme.BG))`，改用主題底色（`#0d1322`）。
- 驗證狀態：尚未實機驗證，需使用者確認第一次開啟 MLB 頁時不再閃白。

## 📌 啟動白閃
- 原因：設了 `QT_WIDGETS_RHI=1` 後，主視窗剛顯示時，在 RHI 第一張畫面送出前約 20~30ms，DWM 會顯示白底，深色主題下很刺眼。把調色盤設成深色無效（白底不是 Qt 繪製出來的）。
- 修法：`utils/win_titlebar.py` 新增 `set_cloak(widget, cloaked)`，以 `DwmSetWindowAttribute` 的 `DWMWA_CLOAK`（13，注意不是唯讀的 `DWMWA_CLOAKED` 14）隱藏視窗；`ui/main_window.py` 的 `showEvent`（非 spontaneous）先 cloak，再以 `QTimer.singleShot(30ms)` 取消。從系統匣還原也會走 show，所以每次非 spontaneous 顯示都處理。
- 診斷方式：獨立程序在視窗顯示期間以 GetPixel 取樣視窗中心。未修正時出現 `#ffffff` 約 20~30ms；以 cloak 修正後測試 4 次皆無白色。
- 測試：`tests/test_win_titlebar.py` 以假的 DWM 驗證 attribute 為 13、值為 1/0、HRESULT 非 0 回傳 False。
- 驗證狀態：診斷腳本層級已驗證；app 實機尚待使用者確認。
